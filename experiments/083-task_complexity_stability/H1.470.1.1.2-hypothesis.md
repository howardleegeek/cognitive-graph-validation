# H1.470.1.1.2: Optimal Dimension Stability Across Task Complexities

## Hypothesis

The optimal representation dimension (currently 816) is NOT stable across different task complexities. As task complexity increases (more steps in the sequence), the optimal dimension will shift higher to accommodate more complex representations needed for longer-horizon reasoning.

## Prediction

1. For 2-step tasks: Optimal dimension will be lower (~768-800)
2. For 3-step tasks (current baseline): Optimal dimension is 816
3. For 4-step tasks: Optimal dimension will be higher (~832-848)
4. For 5-step tasks: Optimal dimension will be even higher (~864-896)

## Rationale

Longer sequences require:
1. More capacity to represent temporal dependencies
2. More separation between different time steps
3. More complex state representations
4. More parameters to model longer-range interactions

Therefore, as task complexity increases, the optimal dimension should increase to provide sufficient representational capacity.

## Experimental Design

Test dimensions [768, 800, 816, 832, 848, 864, 896] across:
1. 2-step tasks (simpler)
2. 3-step tasks (current baseline)
3. 4-step tasks (more complex)
4. 5-step tasks (most complex)

For each dimension and task complexity:
- Train CG model for 15 epochs
- Use 400 train / 100 test samples
- Run 2 runs per configuration
- Measure single-step and multi-step improvement
- Calculate improvement gap (multi-step - single-step)

## Success Criteria

Hypothesis SUPPORTED if:
- Clear monotonic relationship: optimal dimension increases with task complexity
- Statistical significance in dimension shifts across complexities

Hypothesis REFUTED if:
- Optimal dimension remains stable at ~816 across all complexities
- No clear pattern or random variation
- Optimal dimension decreases with complexity (counter-intuitive)

## Expected Outcomes

If supported, this would suggest:
1. CG architecture should adapt representation dimension based on task complexity
2. Dynamic dimension allocation could improve performance
3. One-size-fits-all dimension is suboptimal

If refuted, this would suggest:
1. 816 is a robust sweet spot across task complexities
2. CG representation is sufficiently flexible for various complexities
3. Simpler architecture (fixed dimension) is adequate
